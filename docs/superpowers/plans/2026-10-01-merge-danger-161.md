# path-based one-way-door classifier (issue #161)

Board issue #161: "feat(ci): path-based one-way-door classifier overrides
self-graded door" — a deterministic, path-based classifier that overrides an
agent's own self-graded reversibility judgment on a PR (see "Executing
actions with care" in studio lead system prompts — leads already self-assess
whether an action is reversible/irreversible; this adds a hard, path-based
override on top, for CI). This concept does not exist anywhere in the repo
today — greenfield: no PR template, no existing label, no existing
classifier.

The issue body describes the forced-one-way paths in plain English
("secrets/config", "leak gate", "write proxy", migrations, deploy, rescue).
None of those are literal repo paths — they are resolved below against the
real tree (verified to exist at the time this plan was written). Kept here
so a future reader isn't confused by the mismatch with the issue text — see
also the comment above `ONE_WAY_GLOBS` in `merge-danger.ts` itself, which is
the authoritative, lower-drift-risk source (this doc should not be trusted
over the code if they ever disagree).

## Design

### 1. `apps/fleet/scripts/merge-danger.ts` (new)

Same house style as `apps/fleet/scripts/english-check.ts` (shebang,
`import.meta.main` CLI guard, pure exported functions, no subprocess needed
for the unit tests, "deliberately small — a noisy check gets disabled"
philosophy).

- `ONE_WAY_GLOBS: { pattern: string; why: string }[]` — the table above,
  verbatim.
- `classify(changedFiles: string[]): { oneWay: boolean; matched: string[] }`
  — pure. `oneWay` is true iff any changed file matches any glob. `matched`
  lists every matching CHANGED FILE (not the glob pattern), de-duplicated in
  encounter order. Single-file entries (no `*`/`**`) match by exact string
  equality; the rest use `Bun.Glob` (this repo is bun-first, and `Bun.Glob`
  already supports `**`).
- CLI entry (`import.meta.main`): reads newline-separated changed file paths
  from stdin (blank lines ignored), calls `classify`, prints one line of
  JSON to stdout (`{"oneWay":true,"matched":[...]}`.) Always exits 0 —
  classification is informational, never a pass/fail gate on its own.

### 2. `apps/fleet/test/bun/merge-danger.test.ts` (new)

Same style as `apps/fleet/test/bun/english-only.test.ts` — `bun:test`,
`describe`/`test`/`expect`, relative import of the pure functions, comments
citing #161 where useful.

- One case per glob class (12) — a changed-files list with exactly one file
  under that class asserts `oneWay === true` and `matched` contains that
  file.
- Docs-only change (`docs/operations.md`, `README.md`) → `oneWay === false`,
  `matched` is `[]`.
- Mixed change (one dangerous path among several safe ones) → `oneWay ===
  true`, `matched` contains ONLY the dangerous path(s).
- Empty file list → `oneWay === false`.

Written FIRST against a nonexistent `merge-danger.ts` (RED — import fails),
committed, pushed; then `merge-danger.ts` implemented to make it pass
(GREEN).

### 3. `.github/workflows/one-way-door.yml` (new)

Same shape as `.github/workflows/english-check.yml` — NO path filter (every
PR must be classified, including docs-only ones, so a two-way-door PR is
correctly reported as such). `on: pull_request:` (all types) +
`workflow_dispatch:` only — no `push:` trigger, since there is no PR to
label on a push to `main`.

`permissions: pull-requests: write` at the workflow (or job) level, needed
for `gh pr edit --add-label`/`--remove-label` with the default
`GITHUB_TOKEN`.

Steps: `actions/checkout@v4` with `fetch-depth: 0` (cheap for this repo's
size, and simplest way to guarantee the base SHA is present to diff
against), `oven-sh/setup-bun@v2` (mirrors the other two workflows), then:

1. Compute changed files: `git diff --name-only
   ${{ github.event.pull_request.base.sha }} ${{ github.sha }}`.
2. Pipe into `bun run apps/fleet/scripts/merge-danger.ts` for the JSON
   verdict.
3. Parse with `jq` (preinstalled on `ubuntu-latest`) for `oneWay`/`matched`.
4. `gh label create one-way-door --color d93f0b --description "..." --force`
   — idempotent, ensures the label exists before it's ever applied.
5. `oneWay == true` -> `gh pr edit <number> --add-label one-way-door`;
   `false` -> `gh pr edit <number> --remove-label one-way-door` (removing an
   absent label is a no-op, so this is idempotent either direction).
6. Append the matched paths to `$GITHUB_STEP_SUMMARY` — the "check posts the
   list of matched paths" requirement is satisfied by the job's own output,
   independent of the label.
7. The job always exits 0 — informational classification, not a merge gate.

Not end-to-end testable from inside this container (no live PR exists yet
for this branch) — got the YAML right by careful reading/dry-reasoning
against the two existing workflows' real, working shape; QA verifies the
live firing once the PR is open.

### 4. `docs/operations.md`

New `### One-way-door classification` subsection inside `## CI`, right
after the existing workflow table, same terse "measured, not predicted"

## Blocked: workflow file

`.github/workflows/one-way-door.yml` could not be pushed to this branch:
this container's git/gh credential is a GitHub App installation token
scoped to exclude writes under `.github/workflows/**` (a hard platform
restriction, not a bug to fix), and GitHub rejected the push with
"refusing to allow a Personal Access Token to create or update workflow
.github/workflows/one-way-door.yml without workflow scope". A maintainer
with a `workflow`-scoped credential needs to add the file by hand — either
paste the content below into `.github/workflows/one-way-door.yml` via the
GitHub web UI, or push it from their own PAT — then re-run `bun run
english-check` to confirm the new file doesn't trip it.

```yaml
name: One-Way-Door Classifier

# Board issue #161: a deterministic, path-based classifier that overrides an
# agent's own self-graded reversibility judgment on a PR. No paths filter —
# every PR must be classified, including docs-only ones, so a two-way-door
# PR is reported as such and the `one-way-door` label is removed if a prior
# push had added it. This is informational, not a merge gate: the job
# always succeeds, win or lose on the classification itself.

on:
  pull_request:
  workflow_dispatch:

permissions:
  pull-requests: write

jobs:
  classify:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - uses: oven-sh/setup-bun@v2
        with:
          bun-version: latest

      - name: Classify changed files
        id: classify
        run: |
          verdict=$(git diff --name-only "${{ github.event.pull_request.base.sha }}" "${{ github.sha }}" \
            | bun run apps/fleet/scripts/merge-danger.ts)
          echo "verdict=$verdict" >> "$GITHUB_OUTPUT"
          one_way=$(echo "$verdict" | jq -r '.oneWay')
          matched=$(echo "$verdict" | jq -r '.matched | join("\n")')
          echo "one_way=$one_way" >> "$GITHUB_OUTPUT"
          {
            echo "### One-way-door classification (#161)"
            echo
            echo "\`oneWay\`: **$one_way**"
            echo
            if [ -n "$matched" ]; then
              echo "Matched forced one-way-door paths:"
              echo
              echo "$matched" | sed 's/^/- /'
            else
              echo "No forced one-way-door path matched — two-way door."
            fi
          } >> "$GITHUB_STEP_SUMMARY"
          echo "matched paths:"
          echo "$matched"

      - name: Ensure the one-way-door label exists
        env:
          GH_TOKEN: ${{ github.token }}
        run: |
          gh label create one-way-door \
            --color d93f0b \
            --description "Deterministic path-based override: this PR touches a forced one-way-door path" \
            --repo "${{ github.repository }}" \
            --force

      - name: Apply or remove the one-way-door label
        env:
          GH_TOKEN: ${{ github.token }}
        run: |
          if [ "${{ steps.classify.outputs.one_way }}" = "true" ]; then
            gh pr edit "${{ github.event.pull_request.number }}" --add-label one-way-door
          else
            gh pr edit "${{ github.event.pull_request.number }}" --remove-label one-way-door
          fi
```
