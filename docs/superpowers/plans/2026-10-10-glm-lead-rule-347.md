# Tighten GLM lead rule: comment + plan-doc brevity (issue #347)

Issue: https://github.com/rafarc21/fleetflare/issues/347. Tier GLM-OK. Refs
#302 (the rule this extends), never closes.

## Problem

Across 7 GLM PRs (#308, #310, #339, #342-#345) the recurring review finding
is verbosity: 10-28-line docblocks, plan/task numbers cited in code
comments, plan docs 110-243 lines. GLM calls cost ~1 min each; long prose
is context and review budget burned every round.

## Change

`src/llm/lead-rule.ts` GLM_LEAD_HOUSE_RULE gains one bullet block:

- Code comments: 1-2 lines of WHY only — never history, never plan or task
  numbers.
- Plan doc ≤ 40 lines; PR body carries the evidence, no evidence files.

Test: `test/glm-lead.provision.test.ts` gains one it pinning the new text
(1-2 lines / WHY / no plan-or-task numbers / 40 / PR body) plus keeps the
existing glm-only render postures already covered there.

## Boundaries

lead-rule.ts + its test file only. No provision.ts change (render channel
unchanged). TDD: extend the rule test first (RED), then edit the rule
(GREEN).
