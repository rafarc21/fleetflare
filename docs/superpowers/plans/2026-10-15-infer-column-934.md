# Plan — #934: fleet ls INFER column — per-studio lead error rate (last 30 min)

Task: https://github.com/rafarc21/fleetflare/issues/934

## Problem

A GLM/kimi/deepseek-led studio blocked on Workers AI 429/5xx reads `running`
in `fleet ls` with every number frozen — silence looks like progress
(2026-10-15: one studio made 0 output for 5h and nobody saw it). The
junior_usage_log table already records every lead inference call
(`mode: "lead"`, written by anthropic-route.ts's logUsage), but `fleet ls`
never reads it.

## Change

1. **Route** — `GET /studio/junior/usage/lead?since=<ms>` in
   src/junior/usage.ts (new `aggregateLeadUsage` + `handleLeadUsageStats`),
   mounted in src/index.ts right beside the existing
   `/studio/junior/usage` mount (line ~117). Reads-only: one GROUP BY
   studio_id over `mode = 'lead'` rows with `ts >= since`, columns
   `calls`, `ok` (SUM of ok, not COUNT of errors — keeps the route additive
   for future ok-shape changes). Access-gated via verifyAccess, exactly as
   handleJuniorUsageStats is. The existing `/studio/junior/usage` route
   cannot filter by mode (its aggregate deliberately EXCLUDES lead rows,
   usage.ts line ~110), so a sibling read-only route is the minimal add.

2. **CLI pure module** — new `cli/infer-format.ts` (pure, no node:*/Bun
   imports, same reason cli/readiness-format.ts's header documents: a test
   under the root tsconfig's type set can import it directly):
   - `export interface LeadInferUsage { calls: number; ok: number }`
   - `export const INFER_WINDOW_MS = 30 * 60 * 1000` (exported so tests pin
     the window, same posture as ACTIVITY_DO_STALE_SECONDS)
   - `export const INFER_BLOCKED_MIN_CALLS = 10`
   - `export function isLeadInferenceBlocked(u: LeadInferUsage | undefined): boolean`
     — true iff `u !== undefined && u.calls >= 10 && ok/calls < 0.5`
   - `export function formatInfer(u: LeadInferUsage | undefined): string`
     — `'-'` when undefined; else `'<ok>/<calls> <pct>%'` where pct is
     Math.floor(ok/calls*100). Example: `{calls: 48, ok: 12}` → `'12/48 25%'`.
     A 100% ok-rate renders `'48/48 100%'`, not `'48/48'`.
3. **CLI wiring** — cli/fleet.ts:
   - `fetchLeadInferUsage(creds, now, fetchImpl)` — one GET to
     `/studio/junior/usage/lead?since=<now - INFER_WINDOW_MS>`, Access
     headers + explicit JSON Accept, 10s AbortSignal.timeout, tagged
     result `{ ok: true, by: Map<string, LeadInferUsage> } | { ok: false,
     message: string }` — never throws, same soft-fail posture as
     openPrsByStudio. A Worker predating the route 404s → `{ok:false}`.
   - `cmdLs`: fire the fetch unconditionally on the table path (ONE extra
     Worker read per ls run — it is a single D1 GROUP BY, not a per-studio
     fan-out, so the #332 review H1 "bare ls never fans out live reads"
     rule is satisfied; a degraded answer renders `'-'` cells, never
     blocks the listing). Print ONE stderr line when the route is
     unavailable: `fleet ls: lead inference status unavailable (<message>)`.
     In `--json` mode, still fetch (cheap), and add `infer?: { calls:
     number; ok: number }` per row ONLY when the route answered for that
     studio (absence = no data, same openPrs contract).
   - `formatTable`: new `inferBy?: Map<string, LeadInferUsage>` last
     parameter (optional — every existing single-studio call site unchanged,
     renders `-`), new `INFER` column between ACTIVITY and CHECKED. Cell =
     `formatInfer(inferBy?.get(s.id))`. When the cell's own threshold fires
     (`isLeadInferenceBlocked`), ALSO append ` inference-blocked` to the
     READY cell text — the READY column is where an operator already looks
     for "this row is lying about being fine" (issue #99 rate-limit
     precedent: a live row's limit overrides the verdict there).
     Implementation: compute `const blocked = isLeadInferenceBlocked(...)`
     before the row array, then the READY cell renders
     `readyOverride(s, now) ?? formatReady(...)` and, when `blocked`,
     appends the marker (never replaces: the underlying verdict still
     shows).
   - `lsJsonRows` (cli/readiness-format.ts): new optional
     `inferBy?: Map<string, LeadInferUsage>` last parameter; per row adds
     `infer` only when the map has an entry (0-call entries included when
     the route reports them).
   - Help text (src/studio/cli-args.ts): ls summary gains `INFER
     ('<ok>/<calls> <pct>%' lead calls in the last 30min, '-' when none; a
     live row with >=10 calls under 50% ok reads 'inference-blocked' in
     READY)`. Keep the existing summary text otherwise byte-identical.
4. **No migration** — the table already exists (0004/0005/0006); read-only
   telemetry touches no schema. merge-danger ONE_WAY_GLOBS does not cover
   src/junior/ or cli/ — two-way door.
