# Rescue-push walks every worktree; `fleet rescue-all` before rollout (board issue #251)

## Background — two losses

1. **cto-d7's ProfilePage work.** `rescuePushCmd` only ever inspected the
   MAIN checkout's own `git status`. `.claude/worktrees/<name>` (a real
   nested `git worktree add`, not a plain directory — issue #217's own
   marker-exclusion fix made this exclusion total, not partial) held a
   member subagent's dirty, never-committed feature. `fleet destroy` ran
   rescue-push, saw a clean main checkout, reported `RESCUE_CLEAN`, and tore
   the container down — the member worktree was never looked at.
2. **cto-ed's 24-minute loss.** A container exit during an image rollout.
   Rollout replacement does not run rescue-push at all (only `recycle`/
   `destroy` do — this is documented separately in
   `skills/fleet-cockpit/SKILL.md`'s existing "rollout eats a lead" section);
   even had it run, the lost commits were already committed locally but had
   no upstream ref (`git push` never ran), so the existing "dirty tree only"
   rescue-push would have reported clean and rescued nothing anyway.

Both gaps close with the same underlying fix: rescue has to walk every
worktree, not just the main checkout, and it has to catch "clean but
unpushed", not only "dirty" — and there has to be a way to run it fleet-wide,
on demand, right before the one event (an image rollout) that replaces every
studio's container with no rescue mechanism of its own.

## The fix

1. **`rescuePushCmd`** (`apps/fleet/src/studio/rescue.ts`) — the exec
   generator, unchanged shape (no `exit`, three quiet outcomes on stdout,
   still runs in the shared `sandbox-default` session), extended two ways:
   - After the main checkout's own dirty-tree handling, it enumerates every
     entry from `git worktree list --porcelain` (run from the main checkout,
     which always knows every worktree registered against the same `.git`)
     and independently inspects and rescues each one it doesn't recognize as
     itself: dirty (beyond markers) gets committed under the same fixed
     fleet identity and pushed to `fleet/rescue/<studio>-<worktree-name>-
     <timestamp>` — the worktree's own `basename` folded into the ref so two
     member worktrees never collide.
   - Both the main checkout and every member worktree also get a new
     "clean, but unpushed" check: `git rev-list --count HEAD --not
     --remotes` — the count of commits reachable from HEAD that no
     remote-tracking ref already holds, whether or not an upstream is even
     configured. A non-zero count pushes HEAD to the same generated ref
     scheme with no commit needed. This is what closes cto-ed's loss:
     committed-but-never-pushed is now rescued exactly like dirty-and-
     uncommitted.
   - `any`/`markers` now track across EVERY worktree, so a clean main
     checkout beside a dirty member still reports the push (never a bare
     `RESCUE_CLEAN`), and "markers-only everywhere" still reports
     `RESCUE_MARKERS_ONLY`.
   - Review-round fix (detached HEAD): the main checkout's pre-existing
     branch-vs-default resolution trusted `git rev-parse --abbrev-ref HEAD`
     to always return a real branch name. In detached HEAD it returns the
     literal string `"HEAD"`, which never equals the resolved default
     branch, so the old comparison fell through to the branch-push path and
     used `"HEAD"` itself as the push target — landing a ref at
     `refs/heads/HEAD` on origin, colliding with git's own special meaning
     for that name. Both main-checkout branches now treat `branch === "HEAD"`
     exactly like "checked out branch is the default": always the generated
     `fleet/rescue/...` ref. The worktree loop never had this hole — it
     always generates a ref regardless of what's checked out.

2. **`RescueResult.pushes`** and `rescuePush` parsing (`apps/fleet/src/
   studio/do.ts`) — a single exec can now emit more than one `RESCUE_PUSHED`
   line (main checkout + N worktrees). Parsing requires every non-blank
   output line to match the `RESCUE_PUSHED <target> <count>` shape or it
   falls through to the existing "unrecognisable output" throw (fail
   closed). `branch`/`files` keep describing the first push, unchanged, so
   every existing caller/test asserting the single-push shape still matches;
   `pushes` (optional, omitted on the single-push case) carries the rest.
   `recycleWithSync`'s pre-destroy logging now iterates `pushes ?? [one
   entry]` so multi-worktree rescues each get their own log line. New
   `StudioDO.rescueNow()` — the per-studio RPC `fleet rescue-all` calls
   through the Worker — gates on `this.ctx.container?.running === true`
   before ever calling `rescuePush` (defense in depth beside the CLI's own
   running-only filter), returns `{ ok:false, error:"not running" }`
   otherwise, and normalizes `pushes` to `[]` on any clean/no-checkout/
   markers-only outcome.

3. **`POST /studio/:id/rescue`** (`apps/fleet/src/studio/routes.ts`) — added
   to `ROUTE_RE`'s action list, calls `stub.rescueNow()`, and redacts
   `result.error` through the same `redactSecrets` boundary `/check` and
   `/provisioned` already apply to container-echoed text (a rejected push's
   stderr can carry a repo URL/credential fragment).

4. **`fleet rescue-all [--repo owner/repo] [--dry-run]`**
   (`apps/fleet/cli/fleet.ts`, argv parsing in `apps/fleet/src/studio/
   cli-args.ts`) — the pre-image-deploy gate. `runRescueAll` is the testable
   core: reads `deps.listStudios()` (the same registry read `fleet ls`
   already uses, never a live container check), filters to `state ===
   "running"` AND `--repo` scope (folded through `repoIdSegment`, the same
   comparison every other repo/studio-id match in this codebase uses), and
   for each target either just logs it (`--dry-run`) or calls
   `deps.rescueStudio(id)` (real wiring: one `POST /studio/:id/rescue` per
   selected studio) and logs `clean` / `rescued <branch> (<n>)` / `FAILED
   <error>` per studio. Exits non-zero if any studio's rescue attempt
   failed, so a deploy script can gate on it. Never touches a stopped
   studio — the running-only filter runs before any exec, same #113 F1
   reasoning `destroyStudio`'s own container-running gate already follows.

5. **`skills/fleet-cockpit/SKILL.md`** — the existing "a rollout replacement
   does NOT run rescue-push" section now tells the operator to run `fleet
   rescue-all [--repo R] [--dry-run]` right before `wrangler deploy`, and
   again once the rollout's own second container replacement lands, instead
   of only "check `fleet ls` by eye".

## Test strategy

Real-git tests, bun-test lane (`apps/fleet/test/bun/*.test.ts`), not tmux —
`rescuePushCmd` is pure string generation exercised against a real
`git init --bare` origin, a real clone, and a real nested `git worktree add`
at `.claude/worktrees/agent-…`, matching Claude Code's actual on-disk layout.
Each finding got its own RED-then-GREEN pass:

- `apps/fleet/test/bun/rescue-push.test.ts` — worktree walk (dirty member
  worktree rescued to its own ref), "clean but unpushed" (both main checkout
  and member worktree), markers-only-everywhere still reports
  `RESCUE_MARKERS_ONLY`, and the detached-HEAD finding's own RED (2 failing:
  `RESCUE_PUSHED HEAD 1` landing on a literal `refs/heads/HEAD` target, both
  the dirty and clean-but-unpushed cases on the main checkout) then GREEN (10
  pass, 0 fail, 23 `expect()` calls) once the `branch === "HEAD"` guard
  landed.
- `apps/fleet/test/bun/rescue-all-scope.test.ts` — `runRescueAll`'s testable
  core against fake `deps`: running-only selection, `--repo` scope,
  `--dry-run`'s report-only branch, per-studio clean/rescued/FAILED
  reporting, non-zero exit on any failure.
- `apps/fleet/test/studio.cli-args.test.ts` — `rescue-all` argv parsing
  (`--repo`, `--repo=`, `--dry-run`, unknown-flag usage error).
- `apps/fleet/test/studio.routes.test.ts` — `/rescue` wired into the
  `ROUTE_RE` action table and the shared "repair verbs name the failing
  side" table, plus the review-round redaction test below.
- `apps/fleet/test/studio.session.test.ts` — `rescuePush`'s multi-line
  parsing (`pushes` populated on 2+ `RESCUE_PUSHED` lines, single-push shape
  unchanged, fails closed on a partially-unparseable output).
