# burn.ts twin FNV loops → one fnv2 — board #448

**Goal:** Fold the three copies of the two-roll FNV-1a-style fold in apps/fleet/src/studio/burn.ts into one private `fnv2(s: string, end?: number): [number, number]` at the FP const block (FP_INIT_A/B, FP_PRIME_A/B at :360-363). fnv2 rolls the first `end` chars of `s` (default: the whole string) through both hashes and returns the raw roll pair `[a, b]`; the clamp lives INSIDE fnv2 (`Math.min(end ?? s.length, s.length)`), since callers pass either nothing (sessionMapKey/realPathMapKey fold the whole string) or a possibly-too-large bound (prefixFingerprint's `end` can exceed the live text, which today clamps via `Math.min(end, text.length)`). Then: `sessionMapKey` (:430-438) becomes `const [a, b] = fnv2(key); return \`${(a >>> 0).toString(36)}${(b >>> 0).toString(36)}\`;` — byte-identical output, no separator. `realPathMapKey` (:550-558) becomes the same one-liner over `fnv2(path)` — byte-identical output. `prefixFingerprint` (:384-394) keeps its `fingerprintOf(a, b)` rendering (base36 with `:` separator) but its inline loop is replaced by `const [a, b] = fnv2(text, end); return fingerprintOf(a, b);`. No behavior change.

**Architecture:** Sweep-6 finding F2 (issue #448, parent sweep #415, doc docs/maintainability/2026-10-12-deep-modules-sweep-6.md §F2). Three byte-identical two-roll FNV-1a-style loops in one file (sessionMapKey :430-438, realPathMapKey :550-558, prefixFingerprint's inline rolls :384-394) share FP_INIT_A/B + FP_PRIME_A/B (:360-363). One algorithm, three shapes — a seeding or collision tweak lands three times. Fold to one fnv2 that returns the raw pair so each caller keeps its own rendering (`fingerprintOf` with separator for content, the short no-separator base36 concatenation for map ids). Pure module-internal fold, no export change; the `pathMapKeyImpl`/`__setPathMapKeyForTest` seam is untouched (:574 and :589 keep referencing `realPathMapKey` directly). measureMember's streaming fold (:1866-1904) is NOT in scope — it snapshots the rolls mid-stream at "\n" boundaries, a shape fnv2 cannot express.
