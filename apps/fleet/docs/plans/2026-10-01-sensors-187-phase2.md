# sensor record-only run script (board issue #187, #168 phase 2)

Design doc (`docs/superpowers/specs/2026-10-01-sensor-task-control-loop-168-design.md`,
#168 phase 1) named two sensors buildable today with no new credential:
CI failures (`fleet-check.yml`, main-only, last 50 runs) and known-flaky
count. #187 is phase 2: turn the design's dampener rule and pinned-issue
visibility mechanism into real, runnable code — still record-only, no
auto-filing, no CI gate.

## What this ships

`apps/fleet/scripts/sensors/run.ts` — pure compute (`dampenerState`, report
builder, state parse/render) plus a thin `import.meta.main` I/O shell
mirroring `scripts/merge-danger.ts`'s shape:

- `dampenerState(current, baseline, slack=1)`: FIRED when
  `current > baseline + slack`, else OK. Implements the design doc's
  absolute-count-plus-slack rule.
- Report builder: takes raw current numbers (CI failures/total,
  known-flaky count) plus the PREVIOUS run's baselines (or null on first
  ever run) and returns each sensor's `{current, baseline, dampener}`.
  First run: baseline = current (never a false FIRED). Later runs:
  baseline = whatever the previous run recorded.
  Persistence happens by rolling each run's own current numbers forward
  into the next run's baseline — no separate state store, just the pinned
  issue's own body.
- State parse/render: the pinned `fleet: sensor burn log` issue's body
  carries a hidden `<!-- fleet-sensor-state ... -->` JSON block (invisible
  in rendered markdown) holding this run's numbers for the next run to
  read back as baseline. Render also puts a markdown table (window,
  current, baseline, dampener), the rate cap line ("3/day (filing
  disabled — record-only)"), and a timestamp — the design doc's
  visibility invariant, minus the auto-filing part it explicitly withheld.
- I/O shell: one `gh run list` (CI sensor), one file read
  (`known-flaky.txt`), one `gh issue list` (find pinned issue by exact
  title), one `gh issue edit`/`gh issue create` (write it back). `--dry-run`
  skips the write, prints the body instead — same escape hatch
  `measure.sh`'s read-only design already relies on, used here so review
  doesn't repeatedly touch the real issue.

## Why record-only, still

#168's own ask (auto-file + CI gate) needs operator sign-off on cap
number, dampener window/slack, and the two blocked sensors (dead-account,
Worker exceptions) — none of that is decided yet. This PR only makes the
two unblocked sensors' numbers and dampener state real and persisted;
wiring it to actually file a board task or fail CI is a separate,
later step, same boundary the design doc itself drew.

## Not in this PR

`.github/workflows/sensors.yml` (schedule + workflow_dispatch wrapper
calling `bun run sensors`) — drafted as text for the PR body, not
committed, since this container's token lacks `workflow` OAuth scope
(same constraint `docs/plans/2026-10-01-test-lies-check-phase2.md`
already hit on `fleet-check.yml`). No Worker/src/D1 change. No new
credential.
